# G3 — Annotated recording acceptance matrix (v0.3.0)

> **Status: implementation added; G1/G2 physical device gates and G3 mobile validation are still pending.** Tests run in headless Chromium do not imply iPhone/Android support.

## Primary behavior

A user selects a playable video, starts voice recording, resumes source playback, then draws a circle/arrow/pen stroke while source playback is running. The source pauses **without stopping the video recorder or microphone**. Strokes are part of the Canvas captured by MediaRecorder. On source resumption, current strokes disappear but **past recorded frames remain unaltered**.

## Automated browser smoke (repeatable local procedure)

1. Build the exact branch with `build-standalone.bat` or normal GitHub Actions. Use `dist/index.html`, not manually edited output.
2. Load a 20-second 640x360 landscape video, ideally with second-markers. In Playwright / Chromium, a microphone track generated by a WebAudio oscillator **may** replace getUserMedia for automated tests. Note this is not a physical microphone.
3. Draw an ellipse while paused and sample the Canvas bitmap inside and outside the outline.
4. Start recording, resume source playback, wait 1-2 seconds then drag circle/arrow/pen via pointer actions. Verify source playback became paused while output time continues.
5. Capture a second Canvas sample before and after Undo/Clear/Play. Evaluate the actual output WebM/MP4 using ffprobe and decoded frames at times when the annotations should be visible and cleared. Do not consider a screen screenshot alone proof that marks reached MediaRecorder.
6. Repeat using portrait input and 320px viewport, compare normalized overlay positions and decoded output. Exercise keyboard/JA/EN and help scroll lock.
7. Verify `connect-src 'none'` and no external requests; verify canonical icon still appears identically in header/favicon.

## Known limitations

- v0.3.0 has no pointer **tap highlight**; that is v0.4.0 work.
- Undo/Clear never affect past recording. Re-recording is the only way to replace a recorded mistake.
- Mark coordinates are normalized to displayed video, assuming browser interpretation of `videoWidth/videoHeight`; rotation metadata and uncommon display transforms still require real-device assessment.
- The Canvas is continuously redrawn for recording, so performance varies by device/frame size. There is a cap of 120 visible strokes and 2500 points per pen stroke.
- Source audio remains off. Exported MIME depends on MediaRecorder support; iOS compatibility is unverified.

Direct inspection of **decoded exported files** found visible yellow ellipse, red arrow and white freehand line in both orientations. This is stronger evidence than only a live Canvas screenshot.

**Clear-on-resume regression:** A separate WebM test drew a yellow ellipse while source playback was paused, then resumed. Decoded output at 1.7s retained the ellipse (~1237 annotation-yellow-like pixels); a later 3.5s frame showed it absent (~26 residual pixels from compression/background). The output timestamp/source timestamp differ because of recording and test interaction delays. Both the live Canvas and encoded result show the correct transition: prior recorded strokes remain in earlier frames, new frames clear them.

**Known remaining test gaps:** physical iPhone/Android pointer/touch and microphone behavior, rotated source metadata, hardware permissions, direct `file://` loading, and native OS video playback. These continue to block G1/G3 acceptance. **PR remains Draft**.
